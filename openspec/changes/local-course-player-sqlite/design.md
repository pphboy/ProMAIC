# Design

## Context

动机见 proposal.md。当前代码的约束如下：

- `lib/import/use-import-classroom.ts` 解析 manifest，先分配媒体，再通过文档聚合写入发布课程；已有失败清理逻辑，应继续复用。
- `lib/export/classroom-zip-types.ts` 定义 formatVersion 1 的 `.maic.zip`；课程、场景、动作和媒体引用必须保持兼容。
- `lib/persistence/server-provider.ts` 暴露具体的 Pg 类型及连接池；库中已有存储接口，但应用层课程库、所有权和模型配置仍直接执行 PostgreSQL SQL。
- `lib/persistence/schema-stores.ts` 枚举 14 个迁移集合，包括默认播放并不需要的生成任务、工作台资料和技能。不能把全部集合照搬进播放器启动。
- `instrumentation.ts`、feature flags、课堂 Pi chat 等多处以 `DATABASE_URL` 判断能力，必须统一替换本地模式的判定。
- 现有导出资源内联逻辑可参考，但导入旧包不能依赖联网补齐。`next.config.ts` 当前 CSP 只有 frame-ancestors，不能满足课程资源本地约束。
- 当前仅有 origin 指向 ProMAIC，未配置 upstream；现有 PostgreSQL 集成测试大多使用 PGlite，不能验证 SQLite 语义。

## Goals / Non-Goals

**Goals:** 保持上游课程模型、路由语义和界面组织；以局部存储适配实现本地默认播放；在真实浏览器和真实磁盘上证明无公网仍可使用；使未来 rebase 的差异集中、可验证。

**Non-Goals:** 不把播放器改成纯浏览器 IndexedDB 应用；不迁移整个生成/工作台后台；不提供多实例共享 SQLite、云存储或自动拉取旧包外部资源。构建和依赖安装可在准备阶段联网，安装好的运行产物必须可离线启动。

## Decisions

### 1. 本机常驻服务与显式本地模式

保留 Next.js / Node.js。使用统一服务端配置解析器选择后端：无显式后端配置时为 SQLite 本地播放；显式 PostgreSQL URL 保留既有路径；冲突配置启动时明确报错。数据根目录拟为 `OPENMAIC_DATA_DIR`，数据库为其中的 `openmaic.sqlite`，媒体在 `assets/`，临时导入在 `tmp/`。路径在文档中固定，不随工作目录意外变化。

本地模式采用稳定的单用户身份，默认监听回环地址，课程库不依赖云登录。已有多用户身份行为留在 PostgreSQL 路径。本地模式的能力声明由后端配置返回，启动、库路由、持久化、课堂和 UI 使用同一判断，不伪造 PostgreSQL URL 来绕过检查。

用户已确认 Windows 独立桌面交付，采用 Electron 包装现有应用。替代方案：系统浏览器启动器不符合用户选择；退回浏览器存储违背 SQLite 目标；删除 Pg 实现会扩大上游冲突。

### 2. 以接口切换存储，不模拟 PostgreSQL

抽取 provider 的最小中性接口及应用级查询仓库。SQLite 实现课程文档/文件夹/所有权元数据、运行时记录、资产注册表和模型配置；可选课堂 AI 涉及的会话也使用 SQLite。共享验证、DSL 迁移、错误语义和 HTTP 契约继续复用。

对 `stage-meta`、`library`、owner-bound store、模型配置、Pi chat 和媒体回收路径中的直接 SQL 分别迁移到仓库方法。默认播放不初始化生成 run、工作台材料、技能、owner merge 等无关表，也不启动对应扫描器；本地模式中尚未适配的 API 在触及 Pg 前返回明确的能力不可用响应，UI 隐藏相应入口。可选 AI 的纯课堂问答链路必须适配，而非把整个工作台作为前置条件。

JSON 使用统一编码边界，时间使用明确的毫秒整数，布尔值和错误映射显式处理。新增独立 SQLite 版本化迁移，不复用 Pg DDL，不以 SQL 字符串替换兼容 JSONB、advisory lock 或 FOR UPDATE。

驱动封装在服务端 adapter 内，优先评估项目最低 Node 22.19 的 `node:sqlite` 是否满足所需稳定 API 和打包；若不满足则选用受该运行时支持的原生 SQLite 绑定并固定依赖。该选择不改变存储契约，必须以最低运行时和生产产物验证后落定。

### 3. 短事务与文件媒体一致性

启用外键、WAL 和有界 busy timeout，写操作由服务端串行调度；事务只包含数据库工作，不跨 await 等待网络或文件 I/O。重入事务明确使用 savepoint 或禁止，不隐式提交。单个课程聚合保存、序号分配和读改写必须原子化。

媒体沿用 opaque asset ID 和内容去重语义。先写同目录临时文件并原子发布，再提交注册表；只有文件完成且媒体校验通过才发布课程文档。文件与 SQLite 无法共用原子事务，因此允许未引用的孤儿文件，禁止已发布文档引用不存在的文件。失败清理和重启回收按引用及宽限期处理；删除课程只移除引用，仍被其他课程引用的字节不得删除。

媒体通过同源路由提供，覆盖音频/视频 Range 请求；只按注册表解析文件，不能把 ZIP 路径直接当磁盘路径。备份采用停止服务后复制整个数据目录，明确包含 SQLite WAL/SHM 或先完成检查点；不承诺随意热复制单个数据库文件。

### 4. 保留 ZIP 契约并报告资源完整性

继续支持现有 formatVersion 1 包和既有 ID 重映射。导入前校验 manifest、包内媒体索引和路径；必需媒体缺失或版本不受支持时不发布课程。压缩包不是任意 ZIP 文档集合，不引入新课程格式。

应用脚本、播放器字体、图标和样式随本地产物分发。已知常用互动依赖（如 KaTeX、Three.js 及 addons）通过本地资源映射提供；检查实际导入链，避免只改顶层 CDN URL。复用已有资源 inventory/parser，对图片、CSS url、import map 和互动 HTML 做本地重写与依赖诊断。

任意旧包的远程资源不保证都可恢复。未打包且无本地替代的资源记录 URL、场景和资源类型，显示课程完整性提示和场景占位；其他完整场景继续播放。浏览器策略限制课程文档及 iframe 的外部子资源/连接，服务端导入和代理也不代为访问这些 URL。保留现有 HTML 清理与 sandbox，补充互动脚本动态请求的回归测试；不因 CSP 破坏本地 blob/data 媒体和内联互动运行。

### 5. 只有明确 AI 操作可以联网

AI provider 由用户显式配置，本机服务端代理调用；浏览器仍只访问本地服务。允许边界限于已配置的 AI API，不自动开放搜索、网页抓取、云 PDF 解析、遥测或课程资源代理。基础播放只使用包内音轨，缺少音轨时显示文字继续播放，不自动在线 TTS。AI 不可用时仅对应功能失败，课程状态不受影响。

用户主动开启的 AI 问答需要保留本地会话；来自课程包的脚本不能借此获得无交互授权的通用公网代理。现有 endpoint 校验继续保留。

### 6. 上游同步作为维护契约

实施时新增根目录 `AGENTS.md`：固定 upstream 为 `https://github.com/THU-MAIC/OpenMAIC`，跟踪其默认分支；每次维护主动检查上游差异，在干净工作区和恢复点之上用临时同步分支 rebase 本地提交。同步须适配新增功能涉及的持久化和资源依赖，不能以保留旧行为为由默默丢弃上游修复。

保留 Pg 文件和小粒度本地提交，避免批量改名/格式化。记录同步前后 SHA、采用或延期的功能及原因、冲突处理、回归结果。默认不丢弃用户文件、不重写共享分支或强推；遇到必须重写共享历史的情况单独取得授权。规则要求维护时主动检查，不创建无人值守定时任务。本次不执行真实 rebase。

### 7. Windows 独立桌面交付

采用 Electron 主进程创建独立 BrowserWindow，nodeIntegration 关闭，contextIsolation 与 sandbox 开启。Next.js standalone 服务在内置 Node utility process 中运行，仅监听 127.0.0.1，使用系统分配的端口并通过消息传递就绪地址，避免依赖用户 Node 安装。主进程退出和启动失败时回收子进程；单实例锁防止重复启动服务。阻断远端窗口导航和弹窗，课程 iframe 不获得桌面权限。

默认数据路径为 app.getPath("userData") 下的 data，由桌面主进程通过 OPENMAIC_DATA_DIR 传递；资源放在安装目录，用户数据库不得写进安装目录。Windows x64 为首个目标，electron-builder 生成 NSIS 安装包，默认按用户安装且不请求管理员权限；升级不清理用户目录。构建在 Windows runner 上执行以正确收集 sharp/canvas 等平台原生依赖，不把 Linux node_modules 复制进 Windows 包。最初产物未签名，不声称签名或已完成 Windows 实机验证。

选择内置 Node SQLite 驱动时必须以 Electron 实际运行时验证，而不能只用开发机 Node；若使用原生绑定则必须处理 Electron ABI。增加 Windows 安装、中文和空格路径、无系统 Node 环境、关闭回收服务、升级保留数据及断网播放验收。现有 Compose 保留为次要开发/部署途径，不是 Windows 用户的使用前提。

## Risks / Trade-offs

- [Pg 依赖散落在非核心模块] → 统一能力判断，默认模式生产启动与路由测试断言不创建 Pg pool，不仅测试 provider。
- [WAL 不能提供多写者吞吐] → 限定单机单服务，缩短事务，对锁等待有界处理并测试竞争写。
- [文件和数据库提交中断] → 文件先落盘、注册后发布课程；注入中断测试与引用感知回收。
- [互动 HTML 动态访问远端] → 静态诊断配合运行时限制，以浏览器请求记录证明无非 AI 公网访问。
- [上游生成能力超过本次范围] → 明确能力不可用并记录延期；保留可扩展接口，不能把缺失功能伪装成已同步。
- [原生绑定在不同 Node/镜像中不可用] → 验证最低 Node 版本与 standalone/Compose 产物；文档固定可复现安装方法。

## Migration Plan

1. 在独立实现分支加入配置、SQLite 迁移和存储适配，保留 Pg 回归路径。
2. 接通 ZIP 导入、课程库、学习记录和文件媒体；未适配后台按能力门控。
3. 本地化应用资源、加入旧包诊断和可选 AI 问答；验证完整包断网播放。
4. 更新个人安装默认值、部署说明与 `AGENTS.md`；使用真实 ZIP 和重启流程完成验收。
5. 现有 Pg 用户保持显式 Pg 配置；迁往本地版通过导出/导入 ZIP，不自动操作原数据库。回滚恢复旧版本和原配置，保留新数据目录；SQLite 升级前备份，不支持盲目降级 schema。
